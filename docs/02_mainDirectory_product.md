# Продуктовый разбор mainDirectory (пет-проект) — 29.09.2026

Что за бот, как он устроен для пользователя и админа, какой у него стиль и какие фичи переносим в финальный бот.
Технические ошибки — в `00_code_review_mainDirectory.md`, здесь только продукт и логика.
Источник — полное чтение кода `../mainDirectory/bot` (логи и `.env` не читались).

---

## 1. Идея

Бот учебного центра **«АкваСтом Групп»** (Санкт-Петербург): курсы и семинары для стоматологов разных специальностей и уровней.

Три задачи:
1. **Витрина и запись** — каталог курсов с фото и запись «в 2 клика».
2. **База врачей** — профиль с данными для сертификата (ФИО) и для сегментации (специальность, должность, опыт,
   клиника, город). Email собирается ещё и под предложения по **ассортименту компании: цифровое оборудование,
   инструменты, расходные материалы** — база нужна не только курсам, но и продажам.
3. **Рабочее место менеджера** — курсы, справочники, рассылки по сегментам, выгрузки, отметка оплат.

Плюс **рефералка**: у каждого свой код, ссылка показывается в приветствии и профиле
(«приглашайте коллег — получайте постоянные скидки на мероприятия»), счётчик приглашённых.

## 2. Пользователь: как устроено

**Главное меню** (reply-клавиатура): `👤 Профиль` · `🎓 Записаться на курс` · `⚙️ Админ-панель` (только админам).

**/start** — приветствие центра («Здесь вы можете: подобрать обучение, записаться в 2 клика, управлять профилем»),
новому пользователю сразу его реферальная ссылка. `/start <код>` привязывает пригласившего (только при первом заходе).

**Анкета** (одна длинная цепочка):
ФИО (эхо + «Верно / Изменить») → дата рождения («чтобы поздравить в особенный день 🎂», можно пропустить) → город
(«для внутренней статистики», пропуск) → телефон (**только кнопкой «Поделиться номером»**) → email (проверка формата
и домена, пропуск) → клиника (пропуск) → специальности (мультивыбор ✅, пропуск) → должности (мультивыбор, пропуск) →
опыт в годах (пропуск) → **итоговая сводка «Анкета заполнена ✅, проверьте данные»** → «Все верно» / «Заполнить сначала».
На сохранении фиксируется согласие на ПД с версией политики.
После выбора в мультиселекте сообщение с кнопками заменяется итогом («🩺 Специальности: …»), у прошлых вопросов кнопки убираются.

**Профиль**: сводка всех полей (телефон **под спойлером**), реферальная ссылка, кнопки
`📝 Заполнить снова` · `✏️ Редактировать` · `🎁 Мои рефералы` · `🎓 Активные записи`.
Редактирование: меню полей → ввод → «Корректно?» → «✅ … обновлено» + профиль + меню полей снова (можно править подряд).

**Каталог** — карусель: одно сообщение, фото курса, `◀️ n/N ▶️`, `🔔 Записаться` + `📋 Программа`, `⬅️ Назад в меню`.
Курсы «набор приостановлен» скрыты, сортировка по первой дате. В карточке описание обрезано до 400 символов.
«Программа» — полный текст постранично (~1000 символов), `⬅️ Назад к курсу` возвращает на ту же позицию карусели.

**Запись** — одна кнопка, сразу запись без выбора тарифа: «✅ Вы записаны! С вами свяжутся».
Кнопка под карточкой меняется на неактивную «✅ Заявка отправлена» (пасхалка: 5 нажатий — кнопка исчезает).

**Активные записи** — карусель своих курсов + **статус оплаты** (❌ Не оплачено / ➗ Частично / ✅ Оплачено) +
`Выписаться` → «⚠️ Вы действительно хотите выписаться из курса …?» → Подтвердить / Отменить.

## 3. Админ: как устроено

Вход — кнопка `⚙️ Админ-панель` (ID из .env). Владельцу приходит «Бот запущен 🥳» / «Бот остановлен 😔».

Меню: `🎓 Править курсы` · `👥 Взаимодействие с участниками` · `🛠️ Корректировка базы данных` · `🔙 Выход`.

### 3.1 Курсы
**Мастер «Добавить курс»:** название → одно фото («Готово», бот показывает загруженное) → даты списком
(`01.08.2025, 02.08.2025`, длительность считается сама) → лекторы (мультивыбор, в кнопках «Иванов И. И.») →
направления → **описание/программа текстом с форматированием или файлом .docx/.txt** → формат (💻/🏫) →
уровень (🔹/🔸) → статус набора → **виды тарифов мультивыбором** (полный курс / для двух коллег / только теория /
практика) → для каждого: подпись в карточке (подсказка-пример) + цена → **предпросмотр карточки ровно как у клиента** →
Добавить / Отменить.

**Редактирование:** та же карусель, что у клиента, + `✏️ Править курс` → меню полей
(фото, название, лекторы, даты, цены, направления, описание, статус — с подтверждением, формат, уровень).
Отдельно: «Просмотреть каталог», «⛔️ Завершить набор» (не доделано).

### 3.2 Справочники
Специальности, должности, лекторы (ФИО + био): добавить / изменить. Лектора нельзя удалить, если он привязан к курсам.

### 3.3 Работа с участниками
Меню: `📨 Отправить файл / сообщение` · `✅ Проверить подтверждения` · `💳 Проверить оплату` · `📋 Просмотреть записи` ·
`📊 Статистика` · `📦 Экспорт / Импорт` (часть — заглушки, но это **список желаемых функций**).

**Кому отправить:**
- «Участнику курса»: месяц → курсы месяца (название — лекторы — даты) → список участников с телефонами →
  «всем» или одному.
- «Клиенту»: **по фильтрам** (специальности → должности → опыт от/до), **из листа ожидания** (не доделано),
  **по ФИО** (поиск по части; много совпадений — CSV со списком).
  Семантика фильтра: подходит, если есть совпадение **или поле не заполнено** — чтобы не терять тех, кто пропустил вопрос.
- После фильтра: «Найдено N» → `Отправить всем` / `Экспорт в CSV` (ФИО, телефон, email, город, опыт, должности,
  специальности, дата регистрации; UTF-8 с BOM — сразу открывается в Excel).

**Компоновщик:** текст (или «Без текста») → подтвердить → файл **документом** (фото отклоняются: «пришлите как файл 😉»)
или «Без файла» → **предпросмотр**: текст, файл, «👥 Получателей: N» → исправить текст / другой файл /
`🚀 Отправить клиентам (N шт.)`.

**Доставка:** по одному с паузой; под каждым сообщением у клиента кнопка **«✅ Подтвердить получение»**
(фиксируется статус и время — так менеджер видит, кто получил счёт/документ). Админу — **отчёт ✅/❌ по каждому**,
длинный — CSV-файлом.

**Оплата:** поиск участника по ФИО → его курсы → курс → `Оплачено / Не оплачено / Частично`.

## 4. Стиль

- **Тексты:** эмодзи в начале смысловых строк, жирные подписи полей, обращение «Вы», пример формата
  `🔠 <i>Пример:</i> …`, **объяснение зачем** для необязательных полей («поздравим с днём рождения»,
  «для внутренней статистики», «для быстрой связи»), акцент на ценном: «❗ без ошибок — эти данные пойдут в сертификат».
- **Единый словарь иконок.** Профиль: 👤 ФИО · 🎂 ДР · 🏙 город · 📞 телефон · 📧 email · 🏥 клиника · 🩺 специальность ·
  📋 должность · 📊 опыт. Курс: 📚 название · 👨‍🏫 лекторы · 🗓 даты · 🧬 направления · 🏷 формат · 📊 уровень ·
  💸 стоимость · 📌 статус · 📖 описание. Статусы: 🟢 идёт набор · 🟡 лист ожидания · 🔴 набор приостановлен.
  Формат 💻 онлайн / 🏫 офлайн, уровень 🔹 базовый / 🔸 продвинутый.
- **Навигация:** всё списочное — карусель `◀️ n/N ▶️` в одном сообщении (каталог, мои записи, админ-каталог, программа).
- **Подтверждение** перед значимым: ФИО, итог анкеты, выписка, статус курса, новый курс, рассылка.
- **Лёгкий юмор** в мелочах (пасхалка на кнопке, «ЭЭЭЭ, СТОП ✋ фото не принимаю»). Админке — деловой тон.

## 6. Что в продукте не повторяем

- Длинная анкета из 10 шагов до какой-либо пользы → короткая регистрация, остальное — по желанию и в кабинете (сделано).
- «Заполнить снова» с перезаписью всего профиля → только редактирование полей.
- Запись без выбора тарифа и без ответа на повторную запись («Не удалось записаться») → явные исходы (сделано).
- Выбор курса/участника вводом порядкового номера текстом → inline-кнопки и пагинация.
- Выписка удаляет запись → статус «отменена клиентом», история остаётся (сделано).
- Рассылка внутри хендлера с паузами → фоновая задача, админ получает прогресс и отчёт.
- ДР строкой «как ввели», опыт числом лет → дата и год начала практики (сделано).
- Своя специальность текстом → только справочник (решено).
- Ссылка с зашитым именем бота → из `bot.me()` (сделано).

## 7. Открытые вопросы на будущее

1. Поздравление с днём рождения — делаем? С подарком (промокод/скидка) или просто открытка?
2. Реферальные бонусы — какая механика (скидка на следующий курс, накопительно, порог)?
3. Статус оплаты клиенту — показывать всегда или только после выставления счёта?
4. Рассылки компании (оборудование, расходники) — через этого же бота или только курсы?
5. «Подтвердить получение» — только для документов/счетов или для всех сервисных сообщений?
