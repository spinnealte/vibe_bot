# Запуск бота на Amvera

Выбранный способ развёртывания (решение 06.10.2026). Amvera — российский облачный сервис: сам собирает и запускает
приложение из репозитория, даёт базу PostgreSQL и Redis как готовые сервисы и в московском регионе сам направляет
обращения к Telegram через иностранный адрес. Своих серверов и туннеля не нужно.

Составлено по документации Amvera (docs.amvera.ru). **На Amvera этот бот ещё не запускался** — первый запуск
и будет проверкой.

## Что создаётся в Amvera

Три проекта в одном аккаунте (аккаунт — на заказчика):

| Проект | Что это | Тариф |
|---|---|---|
| PostgreSQL | база с клиентами и расписанием | не ниже «Начальный» |
| Redis | шаги незаконченных сценариев | не ниже «Начальный» |
| Приложение | сам бот | «Начальный» (500 МБ памяти хватает) |

Регион — **Москва**: там хранятся данные и там работает бесплатный доступ к Telegram.
Число экземпляров приложения — **1**: защита от флуда и очередь обращений рассчитаны на один процесс.

## Шаги

### 1. База PostgreSQL

Создать базу, задать имя базы, пользователя и пароль (имя `postgres` для базы и пользователя занято).
Реплики не нужны. Записать адрес для подключения изнутри Amvera:

```
amvera-<имя пользователя Amvera>-cnpg-<название проекта базы>-rw
```

### 2. Redis

Создать из «Преднастроенных сервисов». В его переменных добавить **секрет** `REDIS_ARGS` со значением
`--requirepass <придуманный пароль>`. Адрес для подключения:

```
amvera-<имя пользователя Amvera>-run-<название проекта Redis>
```

### 3. Приложение

Создать проект-приложение (окружение Python). В разделе «Переменные» добавить:

| Название | Значение | Секрет |
|---|---|---|
| `BOT_TOKEN` | токен рабочего бота из BotFather | да |
| `OWNER_TELEGRAM_ID` | Telegram ID владельца (число) | нет |
| `DB_HOST` | адрес из шага 1 | нет |
| `DB_PORT` | `5432` | нет |
| `DB_NAME` | имя базы из шага 1 | нет |
| `DB_USER` | пользователь из шага 1 | нет |
| `DB_PASSWORD` | пароль из шага 1 | да |
| `REDIS_URL` | `redis://:<пароль Redis>@<адрес из шага 2>:6379/0` | да |
| `MANAGER_URL` | ссылка на чат менеджера, когда появится | нет |
| `ADMIN_IDS` | другие админы через запятую, если нужны | нет |

Не задавать: `TELEGRAM_PROXY_URL` (доступ к Telegram Amvera даёт сама) и `LOG_DIR` (стартовый скрипт сам
направляет логи в постоянное хранилище `/data`). Тексты согласий выкладывать не нужно: они в коде, новую версию
бот заводит в базе сам при запуске.

После любого изменения переменных приложение нужно перезапустить — иначе они не применятся.

### 4. Код

Адрес репозитория показан на странице приложения в Amvera. Один раз подключить его (из папки проекта):

```
git remote add amvera https://git.amvera.ru/<имя пользователя Amvera>/<название проекта>
```

Отправить код (у Amvera основная ветка называется `master`, у нас — `main`):

```
git push amvera main:master
```

Amvera спросит логин и пароль от аккаунта, соберёт приложение и запустит его. Обновление бота потом —
та же команда `git push amvera main:master` после коммита.

Что делает при каждом запуске стартовый скрипт `amvera_start.py`: ждёт несколько секунд, применяет миграции,
на пустой базе ставит специальности, должности и временные тексты согласий, запускает бота.

### 5. Проверка

- Логи — на странице приложения (приходят с задержкой до 5–10 минут). В них должны быть строки
  `[старт] запускаю бота` и `Связь с Telegram: OK`.
- Написать боту `/start`; у владельца в меню должна быть кнопка «⚙️ Админка».
- В BotFather запретить добавление бота в группы: `/setjoingroups` → Disable.

## Где что хранится

| Что | Где |
|---|---|
| Клиенты, курсы, согласия | PostgreSQL (ежедневные копии делает Amvera, хранятся три последних) |
| Логи: `bot.log`, `admin.log` | постоянное хранилище, папка Data → `logs` |
| Тексты согласий | постоянное хранилище, папка Data → `legal` (загружаются через файловый менеджер Amvera) |
| Код | репозиторий; папка с кодом при каждом обновлении создаётся заново |

## Если что-то не так

| В логах | Что делать |
|---|---|
| ошибка на шаге `миграции базы` | проверить `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`; база должна быть запущена |
| `Нет связи с Telegram API` | проверить `BOT_TOKEN` и что регион приложения — Москва |
| `Terminated by other getUpdates request` | где-то ещё запущен бот с тем же токеном (например, на Вашем компьютере) — остановить его |
| ошибка подключения к Redis | проверить пароль и адрес в `REDIS_URL` |

## Чего здесь пока нет

- Выпуск настоящих текстов согласий версией 1: на Amvera нет консоли, чтобы добавить запись в базу вручную.
  Это будет сделано отдельной функцией, когда появятся тексты.
- Демо-курсы и выдуманные клиенты (`scripts.seed_demo`, `scripts.seed_fake_clients`) на рабочей базе не запускаются.

Запасной способ — свой сервер: `deploy/README.md`.
