# Запуск бота на сервере

Бот ставится и обновляется одной командой с компьютера разработчика. Docker не используется.

## Что нужно

- Сервер в России (база с персональными данными должна лежать в РФ): Ubuntu 24.04, 2 ядра, 2 ГБ памяти, 30 ГБ диска.
- Вход на сервер по SSH под `root`. Удобнее всего по ключу: тогда не придётся вводить пароль.
- На компьютере: Windows с установленным git (OpenSSH в Windows 10/11 уже есть).

### SSH-ключ (один раз)

Создать ключ, если его ещё нет:

```
ssh-keygen -t ed25519
```

Показать открытую часть ключа и вставить её в панели хостера при создании сервера:

```
type %USERPROFILE%\.ssh\id_ed25519.pub
```

## Установка и обновление — одна команда

Из папки проекта:

```
deploy\deploy.cmd root@АДРЕС_СЕРВЕРА
```

Команда упаковывает **последний коммит** (незакоммиченные правки на сервер не попадают), загружает его
и запускает на сервере `deploy/install.sh`.

**Первый запуск** ставит всё с нуля: Python, PostgreSQL, Redis, пользователя `stubbot`, базу с паролем,
зависимости, схему базы и начальные справочники, службу с автозапуском, файрвол и ежедневную резервную копию.
По ходу спросит токен бота и Telegram ID владельца — оба можно пропустить и вписать позже в `/opt/stubbot/.env`.

**Повторный запуск** — обновление: останавливает бота, делает резервную копию базы, обновляет код и зависимости,
применяет миграции, запускает бота. Настройки, база, тексты документов и логи не затрагиваются.

## Что где лежит на сервере

| Путь | Что это |
|---|---|
| `/opt/stubbot` | код бота (принадлежит root — бот его только читает) |
| `/opt/stubbot/.env` | настройки и секреты: токен, пароль базы, ID владельца |
| `/opt/stubbot/legal` | тексты согласий (см. `legal/README.md`) |
| `/opt/stubbot/logs/bot.log` | общий лог |
| `/opt/stubbot/logs/admin.log` | действия админа |
| `/opt/stubbot/backups` | резервные копии базы за 14 дней |

## Команды на сервере

| Задача | Команда |
|---|---|
| Состояние бота | `systemctl status stubbot` |
| Лог в реальном времени | `journalctl -u stubbot -f` |
| Перезапуск | `systemctl restart stubbot` |
| Правка настроек | `nano /opt/stubbot/.env`, затем перезапуск |
| Резервная копия сейчас | `stubbot-backup` |

Как восстановить базу из копии — в начале файла `deploy/backup.sh`.

## После первой установки

1. Если токен не вводили — вписать `BOT_TOKEN` и `OWNER_TELEGRAM_ID` в `/opt/stubbot/.env`, затем `systemctl start stubbot`.
2. Вписать `MANAGER_URL` (ссылка на чат менеджера), если она уже есть.
3. В BotFather запретить добавление бота в группы: `/setjoingroups` → Disable.
4. Написать боту `/start` и проверить, что в меню есть «⚙️ Админка».
5. Настоящие тексты согласий положить в `/opt/stubbot/legal` и выпустить версией 1 (см. `legal/README.md`).

## Если Telegram с сервера недоступен

Установщик в конце сам проверяет это и пишет результат. Если недоступен — нужен туннель через заграничный
сервер: `deploy/tunnel/README.md`.

## Чего здесь нет

- Копии базы лежат на том же сервере. Чтобы пережить потерю сервера, их нужно дополнительно выгружать наружу.
- Демо-курсы (`scripts.seed_demo`) и выдуманные клиенты (`scripts.seed_fake_clients`) на рабочий сервер не ставятся.
